## Windows: запуск без видимых окон

- Автоматические команды, тесты, диагностика, MCP-поиск и хуки не должны открывать окна консолей. Исключение — только явная просьба пользователя открыть интерактивное окно.
- Проверяй дочерние процессы: скрытый родитель не гарантирует скрытые дочерние запуски. Используй прямой запуск executable без shell, `windowsHide: true` и перенаправление стандартных потоков; для PowerShell `Start-Process` обязателен `-WindowStyle Hidden`.
- Vitest работает с `pool: "threads"`. Не переопределяй его на `forks` или `vmForks` на Windows. Интеграционные тесты, запускающие отдельные MCP-серверы, требуют отдельной проверки скрытого запуска.
- Запускай Vitest через проектные npm scripts либо с `node --require ./scripts/windows-test-processes.cjs ./node_modules/vitest/vitest.mjs`. Один `pool: "threads"` не устраняет отдельный запуск Vite `exec("net use")`; проектный preload заменяет его на скрытый `execFile("net.exe", ["use"])` без оболочки.
- Изменение файлов запущенного сервера не обновляет загруженный код. После исправления параметров процессов перезапусти точно сопоставленный сервер и проверь реальные MCP-вызовы; активный watcher может запускать старый Docker/Git-код в ответ на правки исходников.
- При сообщении пользователя о всплывающем окне прекрати повторные запуски вызывающей его команды. Не объявляй проблему исправленной по одному флагу или по отсутствию окна в кратком опросе процессов.

## Основная сборка

- В корне `main` находится нативный SocratiCode V для Windows. `npm run build` собирает приложение и локальный плагин. `npm test` проверяет запуск, индекс, поиск и watcher. `npm run test:codex` проверяет плагин в изолированном профиле.
- Оболочка, управление процессами и сборка находятся в `windows/`. Действующая логика MCP и индексации находится в `src/`. Плагин Codex находится в `plugins/socraticode-v/`.
- `legacy/` хранит предыдущую версию с Docker. Используй её, когда запрос касается старой версии или сравнения. Сборка Windows выполняется из корня.
- Изменения в `runtime/` и сгенерированные MCP-конфиги остаются локальными. Сохраняй индексы при повторной сборке.

## Работа с индексом

- Передавай проверенный абсолютный `projectPath`. Для новых проектов спроси пользователя, нужен ли индекс и граф. После согласия сохрани правила через `codebase_setup`, проверь область через `action: "preview"` и только затем вызови `codebase_index`.
- После первого построения поиск и граф обновляет watcher. Проверяй сообщения о свежести результатов. Для смыслового поиска используй `codebase_search`, для буквального фрагмента передай `mode: "exact"`. Для зависимостей до правки используй граф и анализ влияния.
