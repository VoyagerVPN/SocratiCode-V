# SocratiCode V — установка и обслуживание

Это сборка SocratiCode V 1.16.1-local.9 для локального Codex. Цель — установить именно содержимое этого архива, сохранить общий stateless HTTP и Jina v5 Nano Retrieval. Не подменять его официальным `npx socraticode`: там нет этих исправлений. Работай на машине владельца, отвечай по-русски и проверяй фактическую конфигурацию.

## Перед установкой

1. Корень пакета — папка с этим файлом, `runtime.json`, `setup.mjs` и `server/`. Определи абсолютный путь по диску. Не используй пути компьютера автора. Оставь пакет в постоянной папке, например `%LOCALAPPDATA%\SocratiCode-V`; после регистрации её нельзя удалять. Если пакет перемещён, повтори `setup.mjs`.
2. Проверь Node.js >=20 (предпочтительно установленный Node 24), npm, Codex и работающий Docker Desktop с Linux-контейнерами. Проверь существующие подключения SocratiCode и занятость портов 16335 (MCP), 16333 (Qdrant), 11435 (Ollama). Не завершай чужие процессы и не перезаписывай другой профиль Codex.
3. GPU-профиль рассчитан на NVIDIA, доступную контейнерам Docker/WSL2. Проверь оборудование и доступ GPU. Если подходящего GPU нет, объясни ограничение владельцу до изменения профиля. CPU-вариант возможен, но скорость этой машины не обещай.

## Установка зависимостей и сервера

- Из корня пакета выполни `node install-dependencies.mjs`. Скрипт запускает `npm ci` прямым Node без `npm.cmd`, скрывает дочерние процессы и направляет npm/node-gyp/TEMP в `server/.cache`. Если npm установлен иначе, найди фактический `npm/bin/npm-cli.js` через PATH и каталог Node и передай `--npm-cli <абсолютный путь>`. Не скачивай другую версию Node/npm без проверки уже установленной.
- Выполни `node setup.mjs --check`, затем `node setup.mjs`. Это создаёт только локальную запись `%USERPROFILE%/.local/share/socraticode/installation.json` (на других ОС — в домашнем каталоге). Запись позволяет копии плагина в кэше Codex найти подготовленный сервер. Credentials и `CODEX_HOME` скрипт не меняет. Если найдена другая установка, сначала выясни её назначение; `--replace` используй только для согласованной замены.
- Сборка `server/dist` уже включена. Для доработки: из `server/` сначала `node node_modules/typescript/bin/tsc --noEmit`, затем `node node_modules/typescript/bin/tsc` и `node scripts/copy-assets.mjs`. Не обновляй зависимости автоматически.
- Проверь `node hooks/session-start.mjs`: сервер стартует в фоне или повторно используется; успешный хук ничего не печатает. Он не поднимает Docker-контейнеры и не загружает модель до запроса к инструменту. Версия HTTP должна совпадать с `runtime.json`. Старый процесс другой версии нужно идентифицировать и штатно остановить отдельно, хук не убивает его автоматически.

## Подключение в Codex

1. Уточни фактический личный профиль/`CODEX_HOME`, если установок Codex несколько. Сохрани существующие настройки, не копируй credentials и не меняй глобальный `CODEX_HOME`.
2. Проверь `codex plugin marketplace add --help` и зарегистрируй корень этого пакета как локальный marketplace: `codex plugin marketplace add <путь к пакету>`. Каталог задан `.agents/plugins/marketplace.json`, его источник `.` указывает на этот плагин. Если CLI текущего клиента имеет другой синтаксис, используй его документированный flow; не заменяй HTTP на stdio.
3. Через каталог плагинов Codex выбери источник `SocratiCode V`, установи `socraticode` и разреши его SessionStart-хук. Пакет использует только `http://127.0.0.1:16335/mcp`. Не включай одновременно второй SocratiCode с теми же контейнерами и портами.
4. Начни новый чат/переподключи инструменты. Убедись, что современный MCP 2026-07-28 обнаруживает инструменты. Legacy MCP намеренно отклоняется; если клиент не поддерживает протокол, обнови клиент или сообщи ограничение, не добавляй legacy-обход.

## Обязательная проверка результата

- Discovery и `codebase_health` через фактический клиент Codex. Первый запрос может загружать образы и модель; дождись готовности сервисов, одного Docker `Running` недостаточно.
- Модель: `hf.co/jinaai/jina-embeddings-v5-text-nano-retrieval:F16`, 768 измерений, контекст 2048, префиксы `Query: ` / `Document: `, пакет 8, одно соединение Ollama. Это модель embeddings для поиска, а не генератор русских ответов.
- GPU проверяется `docker inspect socraticode-ollama` (DeviceRequests) и Ollama `/api/ps` на порту 11435: `size_vram > 0` после поискового запроса. `codebase_health` сам по себе не доказывает GPU. Уже существующий CPU-контейнер не превращается в GPU от смены переменной: сначала согласуй его замену с сохранением данных.
- Сделай небольшой собственный тестовый проект с отличительным кодом. Выполни preflight, dryRun, индексирование, дождись завершения индекса и графа; найди этот код русским запросом. Проверь пять одновременно подключённых клиентов. Не тестируй удаление на рабочих индексах.
- Завершай установку только после этих проверок. Чётко сообщи, что проверено, какие ограничения остались. Не обещай показатели быстродействия компьютера автора на другой машине.

## Использование для проектов

- Перед широким исследованием: реальный Git/рабочий корень, `codebase_list_projects { projectPath }`, основной индекс и его источники; затем поиск, символы и связи. Точные известные файлы и строки можно читать обычными локальными инструментами.
- Не индексируй всё дерево только из-за просьбы «изучить». Подготовь `.socraticodeignore`, исключи зависимости, сборки, `.cache`, `.temp`, `node_modules`; на большом дереве сначала `codebase_index { projectPath, dryRun: true }`. Лимиты по умолчанию: 2000 файлов, 20000 фрагментов, 32 MiB UTF-8 текста фрагментов. Неполный dryRun содержит нижнюю оценку. Повышай лимиты лишь для явно выбранного объёма.
- Источник добавляется одной операцией: `codebase_index { projectPath: child, parentPath: parent }`. Уже готовые вложенные индексы видны как источники; вложенные папки без индекса не индексируются автоматически. Старые проекты заранее не перестраивай.
- Legacy/adopted/unverified индекс: сообщи время последней индексации и часовой пояс; только затем пересоздай точно сопоставленный необходимый индекс. Смена модели требует пересоздания нужных индексов.
- Предпочитай компактные ответы. Для продолжения используй `nextCursor` с неизменными фильтрами; `partial`, пропущенные источники и ошибки учитывай. Граф разделён на вертикальные группы `Imports →` и `Dependents ←`. JSON запрашивай для программного разбора.
- Отмена действует между пакетами embeddings, не прерывает текущий запрос GPU мгновенно. После индексирования дождись завершения графа и операции, а не только 100% embeddings. При сбое чтения старые данные сохраняются, но индекс помечается неполным до успешного повторения.

## Обслуживание без потери данных и видимых окон

- Один общий HTTP-сервер обслуживает чаты. SessionStart startup/resume/clear запускает его при первом сообщении; автозапуск Windows не нужен. Хук повторно использует сервис и сериализует параллельный старт.
- Встроенный supervisor останавливает управляемые контейнеры после десяти минут без активных операций. Это штатно; следующий поиск запускает их. Не создавай внешний idle-скрипт, не удаляй Docker volumes из-за простоя. При сбое дождись HTTP-готовности, проверь здоровье, повтори запрос.
- Windows: автоматические команды не открывают окна. Прямой executable, `shell:false`, `windowsHide:true`, перенаправленные потоки; для PowerShell `Start-Process -WindowStyle Hidden`. Контролируй также дочерние процессы.
- Vitest — только threads и запуск через `node --require ./scripts/windows-test-processes.cjs ./node_modules/vitest/vitest.mjs`; обычный Vite может запускать `net use` через оболочку. Не используй forks/vmForks. При сообщении об окне прекрати повторные запуски и установи причину.
- Исходники и лицензии входят в `server/`. Изменение файлов не заменяет загруженный код работающего сервера; после согласованной доработки пересобери и перезапусти точно идентифицированный процесс, затем проверь настоящий MCP.
- На компьютере автора исправлены перечисленные сценарии; полный upstream-suite не заявлен зелёным. Не выдавай сборку или HTTP 200 за полную проверку клиентского workflow.
